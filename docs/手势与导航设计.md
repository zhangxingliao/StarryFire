# 手势与导航设计

> 本文档描述 StarryFire Phone Shell 的手势检测机制、沉浸式 bars 行为，以及 App 级返回导航的设计。
> 状态：**已实现**（对应 `components/sf_gui/phone/sf_gui_phone_shell.c`）。

---

## 1. 设计目标

在 LVGL 的输入设备（indev）事件体系上，实现类 Android 的边缘手势：

- **顶部边缘下滑 / 底部边缘上滑** → 显示状态栏和导航栏（沉浸式模式）
- **顶部下滑（bars 已显示）** → 呼出通知中心
- **底部上滑（通知中心打开）** → 收起通知中心
- **左边缘右滑** → App 级返回：先调 `on_back`，未消费则回桌面

核心挑战：LVGL 中可滚动子控件会消费触摸移动事件，导致 indev 级 `LV_EVENT_GESTURE` 不被触发。

---

## 2. 架构总览

```
sf_gui_phone_shell_init()
  └─ 遍历所有 indev，注册 3 个回调（indev 级别，全局生效）
      ├─ LV_EVENT_PRESSED  → immersive_pressed_cb    边缘检测 + 临时禁用滚动
      ├─ LV_EVENT_GESTURE  → immersive_gesture_cb    方向判断 → 触发对应行为
      └─ LV_EVENT_RELEASED → immersive_released_cb   恢复滚动能力
```

**关键设计决策：手势检测注册在 indev 级别，而非具体 LVGL 对象上。**

这意味着任何 App、任何页面上的触摸都会经过同一套处理逻辑，App 侧无需重复注册手势回调。

---

## 3. 边缘区定义

```c
#define EDGE_ZONE_X  24   /* 左边缘宽度（px）—— 向右滑返回 */
#define EDGE_ZONE_Y  24   /* 上下边缘高度（px）—— 上下滑出状态/导航栏 */
```

| 边缘区 | 起手位置 | 手势方向 | 触发行为 |
|--------|----------|----------|----------|
| 上边缘 | y < 24px | 向下滑 (BOTTOM) | bars 隐藏→显示；bars 已显示→呼出通知中心 |
| 下边缘 | y > screen_h - 24px | 向上滑 (TOP) | 通知中心打开→收起 |
| 左边缘 | x < 24px | 向右滑 (RIGHT) | App `on_back` → 未消费则回桌面 |

> `EDGE_ZONE_*` 是**手势触发区**（触摸人体工学，非视觉尺寸），不随 `SF_UI()` 缩放。

## 4. 临时禁用滚动机制

### 4.1 问题

LVGL 的事件分发流程：

1. `LV_EVENT_PRESSED` → 发送到被按对象
2. 触摸移动 → 如果被按对象（或其祖先）有 `LV_OBJ_FLAG_SCROLLABLE`，LVGL 进入滚动模式
3. 滚动模式下，`LV_EVENT_GESTURE` **不会触发**（被滚动消费）

因此，当用户从边缘起手但按在可滚动控件上时，手势被误识别为滚动。

### 4.2 方案

在 `PRESSED` 回调中：

1. 记录起手坐标，判断是否落在边缘区
2. 如果在边缘区，通过 `lv_indev_get_active_obj()` 获取被按对象
3. 向上查找第一个可滚动的祖先（`find_scrollable_ancestor`，跳过 screen）
4. 临时 `lv_obj_clear_flag(ancestor, LV_OBJ_FLAG_SCROLLABLE)`

在 `RELEASED` 回调中：

1. 用 `lv_obj_is_valid()` 校验指针有效性（防止对象在按下期间被删除）
2. 恢复 `LV_OBJ_FLAG_SCROLLABLE`

```c
// PRESSED
if (s_edge_press) {
    lv_obj_t *pressed = lv_indev_get_active_obj();
    s_disabled_scroll_obj = find_scrollable_ancestor(pressed);
    if (s_disabled_scroll_obj) {
        lv_obj_clear_flag(s_disabled_scroll_obj, LV_OBJ_FLAG_SCROLLABLE);
    }
}

// RELEASED
if (s_disabled_scroll_obj) {
    if (lv_obj_is_valid(s_disabled_scroll_obj)) {
        lv_obj_add_flag(s_disabled_scroll_obj, LV_OBJ_FLAG_SCROLLABLE);
    }
    s_disabled_scroll_obj = NULL;
}
```

### 4.3 安全措施

- `find_scrollable_ancestor` 跳过 `lv_scr_act()`，不对 screen 操作 SCROLLABLE flag
- init 中永久 `lv_obj_clear_flag(scr, LV_OBJ_FLAG_SCROLLABLE)`
- `RELEASED` 回调中用 `lv_obj_is_valid()` 防止悬空指针访问
- `s_disabled_scroll_obj` 在每次释放后置 NULL

## 5. 手势方向处理

```c
static void immersive_gesture_cb(lv_event_t *e)
{
    lv_dir_t dir = lv_indev_get_gesture_dir(indev);

    /* 仅处理边缘区起手的手势 */
    if (!s_edge_press) return;

    /* 上边缘向下滑：bars 隐藏→显示；bars 已显示→呼出通知中心 */
    if (dir == LV_DIR_BOTTOM && s_gesture_start.y < EDGE_ZONE_Y) {
        if (sf_gui_phone_bars_are_visible()) {
            sf_gui_notification_center_show();
        } else {
            sf_gui_phone_show_bars();
        }
        immersive_start_idle_timer();
    }

    /* 下边缘向上滑：通知中心打开时收起 */
    if (dir == LV_DIR_TOP && sf_gui_notification_center_is_visible()
        && s_gesture_start.y > sh - EDGE_ZONE_Y) {
        sf_gui_notification_center_hide();
    }

    /* 左边缘向右滑 → App 级返回 → 系统回退 → 回桌面 */
    /* 桌面/通知中心打开时不响应 */
    if (dir == LV_DIR_RIGHT && s_gesture_start.x < EDGE_ZONE_X) {
        if (sf_gui_notification_center_is_visible()) return;
        if (s_desktop 可见) return;   /* 已在桌面 */

        sf_app_ctx_t *cur = sf_app_get_current();
        if (cur && cur->manifest->ops->on_back) {
            if (cur->manifest->ops->on_back(cur)) return;  /* App 已消费 */
        }
        sf_gui_shell_go_home();       /* 未消费 → 回桌面 */
    }
}
```

## 6. App 侧职责

App **不需要**注册任何手势相关代码。唯一需要做的是在 `sf_app_ops_t` 中实现 `on_back` 回调：

```c
typedef struct {
    esp_err_t (*on_create)(sf_app_ctx_t *ctx);
    void      (*on_start)(sf_app_ctx_t *ctx);
    void      (*on_resume)(sf_app_ctx_t *ctx);
    void      (*on_pause)(sf_app_ctx_t *ctx);
    void      (*on_stop)(sf_app_ctx_t *ctx);
    void      (*on_destroy)(sf_app_ctx_t *ctx);
    bool      (*on_back)(sf_app_ctx_t *ctx);       /* ← 边缘右滑时调用 */
    void      (*on_event)(sf_app_ctx_t *ctx, esp_event_base_t base, int32_t id, void *event_data);
} sf_app_ops_t;
```

### `on_back` 返回值契约

| 返回值 | 含义 | Shell 行为 |
|--------|------|------------|
| `true` | App 已消费（如子页面返回主页面） | 无额外操作 |
| `false` | App 未消费（已在主页面） | **回桌面**（`sf_gui_shell_go_home()`） |

> **注意**：与初版"未消费则无操作"不同，当前设计下未消费的返回手势会**回到桌面**。
> 桌面本身不响应返回手势（在桌面时左边缘右滑被忽略）。

### 实现示例

```c
static bool on_back(sf_app_ctx_t *ctx)
{
    settings_priv_t *priv = ctx->user_data;
    if (priv && priv->pg.cur_page) {
        // 在子页面 → 返回主页面
        settings_show_main(&priv->pg);
        return true;   // 已消费
    }
    return false;      // 在主页面 → 未消费 → Shell 回桌面
}
```

## 7. 沉浸式模式

### 7.1 状态栏 / 导航栏的显示与隐藏

- **显示**：上/下边缘滑动，或任何触摸活动（通过 50ms 定时器检测）
- **隐藏**：5 秒无触摸活动后自动隐藏（通知中心打开时例外，保持显示）

### 7.2 定时器

| 定时器 | 周期 | 用途 |
|--------|------|------|
| `s_idle_timer` | 5000ms, 单次 | 无操作 5 秒后隐藏 bars |
| `s_gesture_timer` | 50ms, 无限 | 检测触摸活动，重置 idle timer |

### 7.3 层级关系

LVGL 9 提供 4 个 display 层（自底向上：bottom → screen → top → sys），top/sys 无条件绘制在
screen 之上。StarryFire 据此**从根上解决系统 UI 被 App 覆盖的问题**，不再依赖手动置顶：

```
lv_scr_act()              ← 内容层（screen layer）
  ├─ s_desktop (launcher) ← 桌面
  └─ app->ui_root         ← App UI 根容器（透明全屏）

lv_layer_top()            ← 系统层（top layer，天然在内容层之上）
  ├─ 通知中心（overlay + panel + banner）
  ├─ status_bar           ← 状态栏
  └─ nav_bar              ← 导航栏
```

创建顺序：通知中心先建、bars 后建（`sf_gui_phone_shell_init`），确保 bars 保持在通知中心
overlay 之上。

> **注意**：初版通过 `sf_gui_phone_bars_to_foreground()` + `lv_obj_move_foreground()`
> 在 screen 层手动排序的方案**已移除**——系统 UI 挂 top 层后无需任何置顶调用。
