# 板级接入文档

> 设计原则：**换板只改 `boards/<name>/`，共享代码零改动。**
> 显示驱动、触摸驱动、引脚、屏幕参数全部通过编译期裁剪（Kconfig）挂在板级组件下。

---

## 一、目录结构

```
boards/
└── <board-name>/                  # 一个板 = 一个 IDF 组件（仅 Kconfig + 配置，无源文件）
    ├── CMakeLists.txt             # idf_component_register() 空组件注册
    ├── Kconfig                    # 板选择 + 引脚 + 屏幕参数（由 sf_hal / sf_gui 引用）
    ├── sdkconfig.defaults         # 板级硬件配置（屏幕/触摸/PSRAM/Flash 大小/分区表）
    └── partitions.csv             # 本板专属分区表（按 Flash 大小裁剪）
```

`boards/` 通过根 `CMakeLists.txt` 的 `EXTRA_COMPONENT_DIRS apps boards` 注册为组件搜索路径，
其 `Kconfig` 自动合并进裁剪菜单。

### 配置来源拆分

默认配置由两份 `sdkconfig.defaults` 合并而成（`SDKCONFIG_DEFAULTS` 用 `;` 分隔，后文件覆盖前文件）：

| 文件 | 内容 |
|------|------|
| 根目录 `sdkconfig.defaults` | **OS/App 通用**：GUI shell、WiFi、NTP、FreeRTOS runtime stats、`CONFIG_IDF_TARGET` 等 |
| `boards/<name>/sdkconfig.defaults` | **板级硬件**：`SF_BOARD_*`、驱动选择、屏幕分辨率、PSRAM/Flash 大小、`CONFIG_PARTITION_TABLE_CUSTOM_FILENAME` |

分区表路径为**相对项目根目录**，如 `CONFIG_PARTITION_TABLE_CUSTOM_FILENAME="boards/esp32s3-touch-lcd-2_8/partitions.csv"`。

## 二、板选择机制

根 `CMakeLists.txt` 逻辑：

1. 环境变量 `SF_BOARD=<name>` 存在 → 使用该板；
2. 否则自动探测 `boards/`：仅一个目录时自动使用，多目录时报错要求指定 `SF_BOARD`；
3. 未显式设置 `SDKCONFIG_DEFAULTS` 时，合并「根目录通用 + `boards/<board-name>/` 板级」两份 defaults（后者覆盖前者）。

### 多板冲突防护

`EXTRA_COMPONENT_DIRS boards` 会让 IDF 把 `boards/` 下**所有**含 `CMakeLists.txt` 的板目录都注册为组件
（所有 Kconfig 会被合并，引脚/驱动配置会互相冲突）。根 `CMakeLists.txt` 通过
`EXTRA_COMPONENT_EXCLUDE_DIRS`（须在 `include(project.cmake)` 之后、`project()` 之前用
`idf_build_set_property` 设置）把**未选中的板目录排除**：

```cmake
include($ENV{IDF_PATH}/tools/cmake/project.cmake)
idf_build_set_property(EXTRA_COMPONENT_EXCLUDE_DIRS "${SF_EXCLUDED_BOARD_DIRS}")
project(StarryFire)
```

效果：只有选中的板目录被注册为组件，未选中的板 Kconfig 完全不参与裁剪，同名引脚符号（如
`CONFIG_SF_PIN_LCD_MOSI`）不会重复定义。

```bash
# 单板（自动探测）
idf.py build

# 显式指定（多板时必须）
SF_BOARD=esp32s3-touch-lcd-2_8 idf.py build
```

## 三、新增一块板的步骤

### 3.1 创建板级组件

```bash
mkdir -p boards/<board-name>
```

`boards/<board-name>/CMakeLists.txt`：

```cmake
# 板级组件：仅提供 Kconfig 与 sdkconfig.defaults，无编译源文件。
idf_component_register()
```

### 3.2 编写 Kconfig

必须提供 `SF_BOARD_*` 板选择选项（用作 `#if` 裁剪标记）：

```kconfig
menu "StarryFire Board: <board-name>"

config SF_BOARD_<BOARD_NAME>
    bool "<board-name>"
    default y
    select SF_HAL_DISPLAY_ST7789
    select SF_HAL_INPUT_TOUCH_CST328
    help
        ...

config SF_HAL_DISPLAY_WIDTH
    int "LCD width (px)"
    default 240
    range 1 1024

config SF_HAL_DISPLAY_HEIGHT
    int "LCD height (px)"
    default 320
    range 1 1024

# 引脚全部以 SF_HAL_*_PIN_* 形式定义，由 sf_hal 组件引用
config SF_HAL_DISPLAY_PIN_MOSI
    int "LCD SPI MOSI GPIO"
    default 45
    range -1 48

# ... 其余引脚 / 驱动参数（见现有 esp32s3-touch-lcd-2_8/Kconfig 为范本）

endmenu
```

关键约定：

- 板选择符号命名：`SF_BOARD_<NAME>`，`<NAME>` 取板目录名的大写形式（`-`/`.` → `_`）。
- 引脚用 `SF_HAL_*_PIN_*` 命名，负值表示未使用（如 SPI MISO）。
- 总线号 / 端口 / channel 同为板级硬件事实，配置在板 `Kconfig.projbuild`：`SF_HAL_LCD_SPI_HOST`
  （SPI host 编号，SPI3_HOST=2 / SPI2_HOST=1）、`SF_HAL_TOUCH_I2C_PORT`（I2C_NUM_1=1 / I2C_NUM_0=0）、
  `SF_HAL_LCD_BL_LEDC_TIMER` / `SF_HAL_LCD_BL_LEDC_CHANNEL`（背光 PWM），值取 ESP-IDF 外设枚举编号。
- 屏幕宽高定义 `SF_HAL_DISPLAY_WIDTH / HEIGHT`——UI 缩放 `SF_UI()` 依赖它们。

### 3.3 编写 sdkconfig.defaults + partitions.csv

以现有 `boards/esp32s3-touch-lcd-2_8/sdkconfig.defaults` 为范本，**只写板级硬件差异**（屏幕/触摸驱动、
分辨率、PSRAM/Flash 大小），OS 通用项已在根目录 `sdkconfig.defaults`，无需重复。再复制该目录的
`partitions.csv`，按本板 Flash 大小调整各分区尺寸，并在 `sdkconfig.defaults` 中设置：
`CONFIG_PARTITION_TABLE_CUSTOM_FILENAME="boards/<board-name>/partitions.csv"`。

### 3.4 接入驱动

在 `components/sf_hal/` 中按 `#if CONFIG_SF_HAL_DISPLAY_<DRIVER>` / `#if CONFIG_SF_HAL_INPUT_TOUCH_<DRIVER>`
编写驱动实现文件；在 `components/sf_hal/CMakeLists.txt` 中按同一条件加入源文件。
新增驱动时在 `sf_hal/Kconfig` 增加驱动选择项，并在板 Kconfig 中 `select` 它。

### 3.5 验证

```bash
SF_BOARD=<board-name> idf.py build
# 确认 build/config/sdkconfig.h 中出现：
#   #define CONFIG_SF_BOARD_<NAME> 1
#   #define CONFIG_SF_HAL_DISPLAY_WIDTH ...
```

## 四、常见问题

| 现象 | 原因 / 处理 |
|------|------------|
| `Multiple boards found in boards/. Set SF_BOARD=<name>.` | 多板目录时未设置 `SF_BOARD` |
| 构建仍用旧板配置 | 删除根目录 `sdkconfig` + `build/` 后重新 `idf.py build`（IDF 在根目录缓存 sdkconfig，旧值会掩盖 defaults 的变更） |
| 引脚/参数改了不生效 | 改动在 `boards/<name>/Kconfig` 或 `sdkconfig.defaults`，确认未被根目录旧 `sdkconfig` 缓存覆盖 |
| UI 尺寸不对 | 确认 `SF_HAL_DISPLAY_WIDTH/HEIGHT` 与实际 LCD 一致（`SF_UI()` 以其短边为基准缩放） |
